What else the agent tried.

Most attempts never reach the database. The rest wait for a person, who reads the exact SQL first.

  1. DROP TABLE public.usersDenied

    DDL is refused by PostgreSQL's own parser before it runs.

  2. DELETE FROM public.usersDenied

    A write with no WHERE clause.

  3. SELECT set_config('role', 'postgres', false)Denied

    Only an allowlist of pure built-in functions is callable.

  4. UPDATE public.orders SET total = 0 WHERE 1=1Held

    It touched more rows than the limit, so it was rolled back and queued.

  5. DELETE FROM public.users WHERE id > 0Held

    public.users is protected. This is the one you just undid.

How undo works.

No point-in-time restore, and nobody else's later writes lost.

The database records every change

A trigger inside PostgreSQL captures each changed row, cascades included, and refuses agent writes that don't carry a single-use token.

Undo goes parents first

Deleted rows come back in foreign-key order, then updates revert, then inserts disappear. That's why the users returned before their payments.

It refuses to overwrite

If a row changed after the checkpoint, or the schema drifted, undo stops and names the row. It never guesses.

The ledger can be checked

Checkpoints are append-only and SHA-256 hash-chained. rowback verify-ledger finds the first altered entry.

One command for your agent.

Claude Code, Cursor, or your own agent over MCP. It gets a URL and a key, nothing else.

What it doesn't cover.

Your security team will ask, so here it is up front. The full model is in SECURITY.md.

  • Infrastructure tokensRowback guards the SQL path. An agent holding a cloud or hosting API token can still delete a volume. Keep those tokens away from agents.
  • Database superusersThey can disable triggers and rewrite the ledger. Ship the ledger's head hash to your SIEM.
  • Some tables, for nowComposite primary keys, and tables with rules, inheritance or their own triggers, are refused rather than guessed at.
  • Schema changesDDL is blocked, not reversible. It goes through your normal migrations.
